# Haval H3 Telemetry

Неофициальное бесплатное Android-приложение для вывода параметров автомобиля на приборную панель Haval H3 со штатной мультимедийной системой.

> [!IMPORTANT]
> Приложение проверено на Haval H3 со штатной ГУ Android 9, код проекта 203. Совместимость с другими автомобилями и версиями прошивки не гарантируется. Проект не связан с Great Wall Motor, Haval или их официальными представителями.

## Возможности

- вывод данных на дополнительный дисплей приборной панели;
- остаток топлива в литрах;
- температура охлаждающей жидкости;
- напряжение 12-вольтового аккумулятора;
- список дополнительных сигналов, доступных в системном сервисе ГУ;
- отдельное включение и отключение каждого показателя;
- настройка позиции и размера шрифта каждого показателя;
- настраиваемый вывод текущей даты на приборную панель;
- сохранение настроек между запусками;
- автоматический запуск после загрузки головного устройства.
- встроенный диагностический экран для определения кнопок руля и доступных камерных интерфейсов.
- экспериментальный полноэкранный вывод камер на приборную панель.

## Совместимость

Подтверждённая конфигурация:

- Haval H3;
- штатная мультимедийная система Android 9;
- код проекта 203;
- приборная панель 1920 × 720;
- системный сервис `gwm_adapter`;
- разрешение `com.gwm.android.adapter.permission.GET_DATA`.

На другой модели GWM/Haval/Tank/ORA приложение заработает только при совместимом системном интерфейсе и конфигурации дисплеев.

## Установка

1. Скачайте APK из раздела [Releases](../../releases/latest).
2. Подключитесь к ГУ через ADB.
3. Установите или обновите приложение:

```powershell
adb install -r .\haval-h3-telemetry.apk
```

4. Запустите приложение:

```powershell
adb shell monkey -p app.havalh3.telemetry -c android.intent.category.LAUNCHER 1
```

На главном экране оставлены три общие настройки: **Автозагрузка**, **Показать** и **Скрыть**. Нажмите на строку нужного датчика, чтобы включить его, изменить положение или размер шрифта.

## Сборка из исходников

Требования:

- JDK 17;
- Android SDK 35;
- Gradle 8.9;
- Android Gradle Plugin 8.7.3.

```bash
gradle --no-daemon assembleDebug
```

Готовый файл появится в `app/build/outputs/apk/debug/app-debug.apk`.

CI автоматически проверяет debug-сборку при каждом push и pull request. Подписанные APK публикуются владельцем проекта в GitHub Releases. Ключ подписи и пароли в репозитории не хранятся.

## Диагностика

Проверка разрешения:

```powershell
adb shell dumpsys package app.havalh3.telemetry |
  Select-String -Pattern "GET_DATA|grantedPermissions" -Context 1,5
```

Журнал приложения:

```powershell
adb logcat -c
adb logcat | Select-String "H3GwmAdapter|H3TelemetryService|Permission Denial|SecurityException"
```

Проверка автозагрузки:

```powershell
adb logcat -d |
  Select-String "H3TelemetryBoot|H3TelemetryService|BOOT_COMPLETED|QUICKBOOT_POWERON"
```

Автозагрузка реагирует на обычную, раннюю и быструю загрузку Android. Настройка и параметры оверлея доступны до разблокировки системы. Если дисплей приборной панели ещё не готов, приложение повторяет запуск в течение десяти минут.

### Диагностика кнопки камеры

В версии `1.3.0-diag` на главном экране есть кнопка **Диагностика**. Откройте экран, затем коротко и долго нажмите дополнительную кнопку левого джойстика. Приложение записывает параметры события, но не перехватывает его и не отменяет штатное включение камеры.

Отчёт содержит:

- события клавиш (`keyCode`, `scanCode`, источник, устройство ввода и дисплей);
- найденные Android-дисплеи и устройства ввода;
- камеры, доступные через стандартный Android Camera API;
- доступность `/dev/video51`, `/dev/video52` и `/dev/video53`;
- проверку известных Binder-сервисов камеры и GWM.

Отчёт можно скопировать или отправить одной кнопкой. Он не содержит серийного номера ГУ, сетевых адресов и персональных данных.

Если нажатие не появляется в отчёте приложения, соберите системный журнал через ADB:

```powershell
adb logcat -c
adb logcat -v time | Select-String "H3Diag|SWC|InputHalService|InputService|CAR.INPUT"
```

Дополнительная проверка камерных интерфейсов:

```powershell
adb shell lshal | Select-String "evs|qcarcam|gwm.*camera|multidisplay"
adb shell service list | Select-String "parking|camera|evs"
adb shell ls -lZ /dev/video51 /dev/video52 /dev/video53
adb shell getprop init.svc.ais_v4l2_proxy
adb shell dumpsys media.camera
```

### Экспериментальный вывод камер

Логи Haval H3 подтвердили следующую цепочку:

- автомобильное свойство `GWM_SWC_CustomSwtSts_Mmed` — `557849799` (`0x21401CC7`);
- системный код кнопки — `1007`;
- короткое нажатие — `[1007,0]`, затем `[1007,1]`;
- удержание — повторяющийся `[1007,2]`, отпускание после удержания — `[1007,3]`;
- состояние штатного AVM — `sys.avm.preview_status`;
- управление штатным AVM — `sys.avm.preview_control_action`.

Начиная с версии `1.5.0-camera-sync-test` приложение не захватывает камеру непосредственно по событию кнопки. Оно сначала позволяет штатной системе запустить AVM, дожидается `sys.avm.preview_status=1`, затем с задержкой подключает диагностический Camera2-поток к приборной панели. При `preview_status=0` поток немедленно закрывается.

В списке датчиков есть строка **Камеры на приборной панели**. В её настройках всю функцию можно включить или отключить; по умолчанию она отключена. При включении штатной камеры выбирается передняя нижняя камера. Системный журнал подтвердил команды левого джойстика: вверх — код `1000`, вниз — `1001`. Приложение обрабатывает отпускание кнопки, поэтому одно нажатие не выполняется дважды.

- джойстик вверх выбирает верхнюю камеру видеорегистратора на лобовом стекле;
- джойстик вниз выбирает заднюю камеру;
- повторное включение камер штатной дополнительной кнопкой возвращает переднюю нижнюю камеру;
- при выключении штатного AVM изображение на приборке закрывается.

Физическая конфигурация ГУ указывает: `0` — задняя, `1` — передняя нижняя, `2` — правая парковочная камера. Номер физического QCarCam-канала не обязан совпадать с Android Camera2 ID. На проверенной ГУ Camera2 ID `2` выводит цветовую тестовую таблицу, поэтому он намеренно не используется как верхняя камера.

Камера на лобовом стекле относится к подсистеме DVR и не опубликована в стандартном Android Camera2. Версия `1.9.0-camera-payload-test` подключается к штатному `CarService` обычным Android-механизмом привязки, формирует команду предпросмотра для фронтального DVR-канала и воспроизводит возвращённый сервисом RTSP-поток. Эта часть требует проверки на автомобиле: интерфейс сервиса не документирован производителем.

Открытая Camera2-сессия сама по себе не означает, что камера передаёт изображение: на проверяемой прошивке виртуальные каналы `0` и `1` обновляли чёрные буферы. Поэтому приложение отдельно проверяет содержимое изображения и сообщает, когда видеобуфер обновляется, но остаётся пустым. Диагностические сообщения записываются с тегами `H3Camera` и `H3Diag`.

## Ограничения и безопасность

- Приложение использует системный интерфейс штатной ГУ, который может измениться после обновления прошивки.
- Экран приборной панели выбирается по конфигурации Haval H3; на другом устройстве расположение элементов может отличаться.
- Проверяйте новые версии на неподвижном автомобиле. Не настраивайте интерфейс во время движения.
- Приложение не отправляет телеметрию в интернет и не содержит рекламы или аналитики. Сетевое разрешение используется только для локального RTSP-потока штатного видеорегистратора.
